AI Fitness Coach · Multi-Agent Orchestration Platform

v1.1 · 2026-09-12 ✅ Phase 0 Foundation 🔴 Phase 1 Building

Architecture at a Glance

PolySync is a server-rendered React + Vite + TypeScript + Firebase + Express web application that orchestrates a 12-agent specialist AI mesh to deliver personalized, adaptive fitness coaching. The Gemini API key is held server-side in server.ts; the client calls the app's own API endpoints and never sees the key.

⚛️
Frontend
React 19 + Vite 6 + TS + Tailwind 4 + Motion + D3 + Recharts
🖥️
Server
Express 4.21 + tsx/esbuild + @google/genai 2.4 + dotenv — port 3000
🔥
Firebase
Auth (Google SSO) + Firestore — 10 user subcollections + public exercise library
🤖
AI Backend
Gemini 3.5 Flash (standard) + Flash Thinking/Pro (reasoning) — server-side only, never in browser
Inherits PolyVerses' multi-agent orchestration pattern — agent network visualization, observability dashboard, human-in-the-loop gates, and per-agent system prompts — but replaces the PM workbench domain with fitness coaching domain logic.

Data Flow Architecture

Onboarding Flow
User signs up (Google OAuth via Firebase Auth)
    → Onboarding screen: collect fitness profile
    → POST /api/fitness/profile (F01 validates)
    → Save to Firestore: users/{uid}/profile
    → Trigger F02: generate initial weekly plan
    → Save to Firestore: users/{uid}/plans/{planId}
    → Redirect to Today's Workout / Weekly Plan
Workout Execution Flow
User taps today's workout
    → GET /api/fitness/plan (current plan from Firestore)
    → User logs sets/reps/weight for each exercise
    → POST /api/fitness/log-workout (F05)
    → Save to Firestore: users/{uid}/workouts/{workoutId}
    → F05 schedules adaptation for end of week
    → If wearable connected: F10 updates wearableData
    → F04 recomputes recovery
Conversational Coach Flow
User sends message in Coach Chat
    → POST /api/fitness/chat (F06)
    → Server fetches: profile, recent workouts,
      current plan, latest recovery score
    → F06 generates response with full context
    → Saved to Firestore: chatSessions/{sessionId}
    → Response returned to client
Daily Digest Flow
Every morning (cron or scheduled function):
    → For each active premium user:
        → Fetch: sleep data (if wearable connected),
          yesterday's workout (if any), today's plan
        → Compose digest message
        → Send push notification via FCM
    → Log: digest sent timestamp per user

12-Agent Orchestration Mesh

Orchestration Pipeline — Workflow Execution
F00 Orchestrator Router → F01 Profile Agent → F02 Workout Generator → F11 Compliance Gate → F05 Plan Adaptor (loop)
Profile → Generate Plan → Compliance Check → Serve Plan → Log Workout → Adapt Plan → (loop)
F00
Orchestrator Router
Master Coordinator — routes requests; manages multi-agent workflows; idempotency; circuit breaker; conflict resolution (MoE council)
✅ ReusedStandard route
F01
Profile Agent
Validates profile; detects contradictions (e.g., beginner + 5x/week advanced); suggests clarifications; normalizes inputs
🔴 Not startedStandard (Flash)
F02
Workout Generator
Generates weekly plan from profile + exercise library; periodization; respects injuries + equipment; daily workouts with sets/reps/rest/RPE
🔴 Not startedReasoning (Flash Thinking)
F11
Compliance Gate
Safety & legal gate — injury conflict check; medical disclaimer; health consent gate; safety thresholds; special mode adjustments (GLP-1, postpartum, hypertension)
🔴 Not startedReasoning (safety-critical)
F05
Plan Adaptor
Adjusts next week: completed/skipped, recovery score, user feedback, progressive overload; deload weeks when needed
🔴 Not startedReasoning (Flash Thinking)
F03
Exercise Library
Exercise metadata lookup; substitution queries (same muscle groups, similar movement, equipment constraints); form cues + common mistakes
🔴 Not startedStandard (lookup)
F04
Recovery Analyst
Wearable data + workout frequency + check-ins → recovery score 0-100; train/reduce/rest recommendation with explanation of factors
🔴 Not startedReasoning (Flash Thinking)
F06
Coaching Chat
NL coach with full user context; routes to specialist knowledge; flags unsafe questions; explains reasoning behind recommendations
🔴 Not startedReasoning (highest quality)
F07
Form Coach
Exercise form cues + common mistakes per exercise; interprets user descriptions of movement feel; suggests form fixes
🔴 Not startedStandard (Flash)
F08
Nutrition Advisor
Calorie/macro estimation based on profile + goals; meal suggestions; dietary preferences; flags medical nutrition questions; integrates with GLP-1 mode
🔴 Not startedStandard (Flash)
F09
Motivation Coach
Check-in + chat tone analysis; dropout risk detection; tone adjustment (encouraging vs. challenging); proactive re-engagement nudges
🔴 Not startedStandard + light sentiment
F10
Data Ingest
Normalizes wearable data from HealthKit/Google Fit/Strava/Garmin/WHOOP/Oura into common schema; handles auth; deduplicates; timestamps; no LLM (ETL, rule-based)
🔴 Not startedRule-based (no LLM cost)

Security Model

🔐 Auth & API Security
  • Firebase Google SSO — single sign-on via Google OAuth; email verification required for write operations
  • API key isolation — Gemini API key held server-side only in server.ts; never shipped to browser; client calls own API endpoints
  • x-user-id header auth — all /api/fitness/* routes require Firebase Auth uid passed as x-user-id header
  • Sandbox fallback — if GEMINI_API_KEY is missing, server generates high-fidelity simulated outputs so the app remains functional
🛡️ Firestore Security Rules
  • Default-deny — all access denied unless explicitly allowed
  • Per-user ownership — users can only read/write their own users/{uid}/... collections
  • Email verification required — write operations gated on request.auth.token.email_verified
  • Validated schemas — field-level validation for each collection (types, ranges, enums)
  • Immutable fields protected — createdAt, workout logs cannot be modified after creation
  • Health data consent gate — wearable data read/write blocked without explicit healthDataConsent flag
🏥 Health Data Protection
  • Consent flag gate at API level (F11) + Firestore rules
  • Data encrypted at rest by Firebase
  • Not used for model training
  • GDPR/CCPA deletion pipeline via Firebase Admin SDK
⚠️ Compliance & Safety
  • All AI-generated workout content includes fitness disclaimer
  • Medical queries get disclaimer + professional referral
  • F11 Compliance Gate: injury conflict check before serving plans
  • Conservative exercise recommendations for beginners
📋 Compliance Checklist
  • GDPR Art. 6 lawful basis (consent for health data)
  • GDPR Art. 17 right to erasure (data deletion pipeline)
  • GDPR Art. 20 right to portability (data export)
  • CCPA opt-out mechanism
  • HIPAA-aware (not a covered entity, but health data treated with care)
