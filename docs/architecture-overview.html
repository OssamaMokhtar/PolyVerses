Every Data Flow — Step by Step
■ ONBOARDING FLOW User signs up (Google OAuth) → Firebase Auth creates UID FitnessOnboarding form: goal/level/injuries/equipment/ days/session/focus/biometrics/consent/disclaimer → POST /api/fitness/profile → validate goal+level → saveProfile(uid) → save to users/{uid}/profile/current → POST /api/fitness/generate-plan → buildPlanGenerationPrompt(profile) → Gemini F02 → parse WeeklyPlan JSON → save plan → save to users/{uid}/plans/{planId} → redirect to Today's Workout / Weekly Plan ■ WORKOUT EXECUTION FLOW User taps today's workout → GET /api/fitness/plan → latest plan from users/{uid}/plans → getTodayWorkout() → find day by dayIndex → render exercise cards with set logging → user logs reps/weight per set → exerciseLogs state → POST /api/fitness/log-workout → save workout → generateAdaptation(uid, workout) → Gemini F05 → adapted plan → save to users/{uid}/plans/{newPlanId} → alert('Workout logged!') → fetchPlan() → reload ■ COACHING CHAT FLOW User sends message in Coach Chat → POST /api/fitness/chat → getProfile(uid) → build context string → fullPrompt = Context + User question + F06_SYSTEM_PROMPT → Gemini Flash Thinking → responseText → save userMsg + assistantMsg to users/{uid}/chatSessions/{sessionId} → return { response, sandbox } ■ DAILY DIGEST FLOW (DESIGNED, NOT IMPLEMENTED) Every morning (cron) → for each active premium user: → fetch sleep data (wearable) + yesterday's workout + today's plan → compose digest: workout recap + recovery score + today's workout + motivation → send push notification via FCM → log digest sent timestamp

Security Model — Full Detail
Authentication:
Google OAuth via Firebase Auth → UID. Client sends x-user-id header. Server requireAuth() extracts UID, 401 if missing. Email verification required for writes (Firestore rules).
Firestore Rules:
Default-deny. Per-user ownership (users/{uid}/...). Email verification for writes. Validated schemas per collection. Immutable fields (createdAt, workout logs) protected. healthDataConsent checked before wearable data read/write.
API Key Security:
Gemini key in GEMINI_API_KEY env var — server-side only, never shipped to browser. Errors don't leak key. Sandbox fallback if key missing or equals "MY_GEMINI_API_KEY".
Health Data:
Consent flag gate at API + Firestore rule level. Encrypted at rest by Firebase. Not used for model training. GDPR/CCPA deletion pipeline via Firebase Admin SDK (future).
Compliance:
All AI workout content includes disclaimer (App.tsx line 349–351). Medical queries: F06/F08 system prompts include safety rules (recommend professional, don't give medical advice). Injury-exercise conflicts filtered in selectExercisesForGoal (line 866–872). Special modes (GLP-1, postpartum, injury rehab) designed but not implemented.
