Governance Wrappers

Token tracking · Budget checks · Circuit breakers · Cache

  • recordTokenUsage Before/after each call
  • checkSessionBudget 200K/session → 429
  • checkCircuitBreaker Per-tier failure tracking
  • getCachedContext 24h TTL · 100 entries

Layer 3

Knowledge + Distillation

~233K tokens/week per 100 users · Batched · Scheduled

Indexes Firestore data into a searchable brain:

  • FitnessNote Indexes workouts, check-ins, chats, recovery, wearables
  • FitnessClassifier Type, entities, date, decision_made, open_questions
  • Distillation Weekly gist → Monthly summary → Quarterly principle
  • GraphEdges Links workouts → check-ins → recovery → plans

New files: knowledge-types.ts · distillation-scheduler.ts · context-cache.ts

Cross-Cutting

Observability + Human Gate

/api/budget — session tokens, agent breakdown (F00–F11), circuit breaker state, cache stats, distillation stats. /api/fitness/gates/:id/decide — human gate for medical queries (F11) and significant plan changes (F05). /api/fitness/think — recall from indexed fitness data without burning a capable model. /api/fitness/specialist — invoke F00–F11 with governance wrapper + assembled context.

12-Agent Mesh — Models & Token Profile
F00
Orchestrator Router
Routes user requests to agents; orchestrates multi-agent chains (generate plan, compliance check, adapt)
Flash · ~1K/call
F01
Profile Agent
Validates + structures fitness profile; detects contradictions (advanced + no equipment)
Flash · ~2K/call
F02
Workout Generator
Generates weekly plan from profile + exercise library; progressive overload; distributes across days
Flash Thinking · ~8–15K
F03
Exercise Library
Serves exercise metadata; handles substitution queries (same muscle, matching equipment)
Flash · ~1K/call
F04
Recovery Analyst
Computes 0–100 recovery score from sleep/HRV/RHR/workout frequency/energy; recommends train/reduce/rest
Flash Thinking · ~2K/call
F05
Plan Adaptor
Adjusts next week based on completed/skipped workouts, recovery scores, feedback; progressive overload
Flash Thinking · ~4–8K
F06
Coaching Chat
Conversational coach; answers with context from profile, workouts, plan, recovery, wearables
Flash Thinking · ~4–12K
F07
Form Coach
Form cues + common mistakes per exercise; interprets user's movement feel description
Flash · ~1–2K
F08
Nutrition Advisor
TDEE estimate + macro targets; meal timing; practical food suggestions; medical disclaimer
Flash · ~2–4K
F09
Motivation Coach
Analyzes check-in sentiment; detects dropout risk; generates motivational messages; adjusts tone
Flash · ~1–2K
F10
Data Ingest
Normalizes wearable data (HealthKit/GoogleFit/Strava/Garmin/WHOOP/Oura) into common schema — ETL, no LLM
No LLM · 0 tokens
F11
Compliance Gate
Safety gate; checks exercises against injuries; enforces disclaimers; blocks medical advice; health consent gate
Flash Thinking · ~2K

Knowledge Layer — Data Model
📝
FitnessNote — atomic unit of the fitness brain
id string (UUID) · uid string · source_collection 'workouts' | 'checkIns' | 'chatSessions' | 'recovery' | 'wearableData' | 'plans' · source_type 'workout_log' | 'check_in' | 'chat_message' | 'recovery_assessment' | 'wearable_snapshot' | 'weekly_plan' · verbatim_text string · classifier FitnessClassifier · para_bucket Project | Area | Resource | Archive · project_id string? (e.g. "goal_build_muscle") · distillation_level 1|2|3|4 · gist string? · summary string? · principle string? · engagement_score number · graph_edges GraphEdge[]?
🏷️
FitnessClassifier — classifies each indexed note
type 'workout' | 'check_in' | 'chat' | 'recovery' | 'nutrition' | 'form' | 'motivation' | 'plan' · entities string[] (exercises, body parts, supplements, goals) · date string? · decision_made boolean (plan change, rest recommendation) · open_questions string[] (unanswered user questions)
🔗
GraphEdge — links related fitness data
target_type 'note' | 'workout' | 'exercise' | 'goal' | 'check_in' | 'recovery' · target_id string · relation 'PART_OF_WEEK' | 'FOLLOWS' | 'CITES' | 'RELATED_TO' | 'RECOVERED_FROM' | 'PAIN_REPORTED_FOR' · direction 'outgoing' | 'incoming'
📊
BudgetSnapshot — /api/budget response
session_tokens_used number · session_budget 200000 · session_remaining number · weekly_tokens_used number · weekly_tokens_budget 1500000 · agent_breakdown { F00: n, F01: n, ... F11: n } · circuit_breakers { tier, status, reason? }[] · cache_stats { size, max: 100, hit_rate_estimate } · distillation_stats { level2_run_count, level3_run_count, level4_run_count, tokens_distilled_this_week }
