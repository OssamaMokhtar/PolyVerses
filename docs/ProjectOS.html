1 Executive Summary
Product Vision
The AI fitness coach that adapts to you — your workouts, your recovery, your progress — all powered by multi-agent AI reasoning that knows your body.
Mission
Democratize coach-quality adaptive fitness programming at $12–15/month, using a 12-agent AI mesh to generate, adapt, and explain every coaching decision with full observability.
North Star Metric
Weekly Active Coached Users
Users who complete ≥1 workout guided by the AI coach per week — the single best predictor of retention and revenue.
Strategic Objectives
🎯 Product-Market Fit (Weeks 1–12)
Ship MVP (onboarding → plan → workout → adapt loop). Achieve >70% onboarding completion, >50% first-workout completion, >40% 7-day retention.
🧠 AI Differentiation (Weeks 6–20)
Ship conversational coach (F06) + recovery-based adaptation (F04/F05). Establish multi-agent architecture as a defensible moat vs. single-model competitors.
💰 Revenue & Scale (Months 3–18)
Launch premium tier ($12/mo) + elite ($20/mo). Reach 10,000+ users and $10K+/mo ARR. Expand to multi-wearable aggregation and GLP-1 specialization.

The fitness coaching market has a fundamental gap: people want personalized, adaptive coaching but can't afford human coaches ($100–150/month), and existing apps offer static plans that don't react to recovery, wearables data, or daily readiness.

Key Market Drivers
📱 Wearable Proliferation
100M+ Apple Watch users, 50M+ Garmin, millions of WHOOP/Oura users globally. 78% of fitness app users own a wearable. Yet <10% of apps use wearable data for coaching decisions — massive whitespace.
🤖 LLM Maturity for Coaching
LLM-based agentic coaching is 47.2% of the agentic AI market. Multi-agent reasoning, tool use, and long-context understanding have matured to production quality in 2025–2026.
💊 GLP-1 Segment Explosion
Millions on GLP-1 agonists (Ozempic, Wegovy, Mounjaro, Zepbound) need strength-preserving, recovery-aware programming. No major fitness app serves this segment. First-mover advantage.
💰 Human Coach Affordability Gap
Human coaches cost $100–150/month (Future, Caliber). 90% of consumers cannot afford this. AI coaching at $12–15/month captures the middle market — premium quality at 10% of the cost.

Economic: $6.2B market growing at 25.1% CAGR. Consumer spending on fitness apps resilient. AI coaching at $12–15/mo is accessible even in downturns vs. $150/mo human coaches.
Social: Fitness culture is mainstream; wearable adoption is high; GLP-1 use is normalized and growing; AI acceptance in health/fitness is increasing post-2023.
Technological: Gemini 3.5 Flash/Pro, HealthKit JS API, Google Fit REST API, Firebase, React/Vite ecosystem all mature and production-ready. Wearable sensor accuracy improving.
Legal: Fitness advice liability — mitigated by disclaimers + F11 Compliance Gate. Health data privacy — GDPR/CCPA compliant by design. No medical device regulation triggers (general wellness, not diagnosis).
Environmental: Minimal — software-only product, cloud-hosted. Low carbon footprint relative to hardware-dependent competitors (Tempo, Peloton, Vi).

Product Vision Board
INSIGHT
People who track fitness data (wearables) don't get personalized coaching from it. Human coaches are too expensive ($150/mo). Static workout apps lead to plateaus and churn.
COMPLICATION
Building a coaching AI requires domain expertise (exercise science), multi-agent architecture, wearable integrations, safety compliance — all expensive and complex. No single-model app does this well.
RESOLUTION
A 12-agent AI mesh that generates adaptive weekly plans, coaches via chat with full context, analyzes wearable data for recovery, and adapts every decision — at $12–15/month.
SUCCESS
Users who complete workouts weekly, see progress, feel coached — and stick around. 7-day retention >40%, 30-day >20%, MRR growth to $10K/month by Month 6.

10 Enterprise Architecture
Architecture Principles
1. Multi-Agent First
Every coaching decision is produced by a specific specialist agent with a clear system prompt, inputs, and outputs. No single-model black box. Traceability is a feature, not an implementation detail.
2. Safety by Design
F11 Compliance Gate is never optional. Injury conflicts are flagged. Medical advice is blocked. Disclaimers are everywhere. Conservative defaults for beginners.
3. Data Minimization
Collect only what's needed. Health data requires explicit consent. No health data used for model training. GDPR/CCPA deletion is a first-class feature, not an afterthought.
4. Server-Side AI Keys
Gemini API key is held server-side only. Client never sees it. All AI calls go through the Express API layer with agent-specific system instructions.
5. Recovery-Aware Adaptation
The platform's core differentiator. Every workout plan is a function of the user's current recovery state, not a static document. Wearable data + check-ins feed recovery score.
6. Incremental Delivery
Ship MVP (onboarding → plan → workout → adapt) first. Add chat, wearables, motivation, monetization in phases. Each phase delivers standalone value.

15 AI Strategy
AI Vision
"The AI fitness coach that adapts to you — every decision traceable, every recommendation explained, every workout responsive to your body's daily state."
PolySync's AI strategy is built on multi-agent reasoning — not a single chat prompt. Each of the 12 specialist agents has a defined role, system prompt, input schema, output schema, constraints, safety rules, and tone. The Orchestrator (F00) routes requests to the right agent(s) and manages multi-agent workflows. This architecture is the product's primary moat: no competitor uses multi-agent architecture, and it cannot be replicated by simply swapping in a better model.
AI Architecture — LLM + Agent + Prompt Layers
LLM Layer
Provider: Google Gemini 3.5 (via @google/genai 2.4)
Models used:
• Gemini 3.5 Flash — standard agents (F01, F03, F07, F08, F09, F00)
• Gemini 3.5 Flash Thinking — reasoning agents (F02, F04, F05)
• Gemini 3.5 Pro — highest-quality agents (F06 Coaching Chat, F11 Compliance Gate)
Key design: Server-side only. Never shipped to browser. Agent-specific systemInstruction per endpoint. Sandbox fallback if GEMINI_API_KEY missing. Temperature 0.7 for creative agents, lower for factual. ResponseMimeType: application/json for structured outputs.
Agent Layer
12 agents (F00–F11), each with:
• Role + expertise definition
• Input schema (what data they receive)
• Output schema (strict JSON for programmatic use)
• Constraints (e.g., "never contradict declared injury")
• Safety rules (e.g., "medical queries → disclaimer + redirect")
• Tone (e.g., "encouraging but factual")
Orchestration: F00 Router routes single-agent or multi-agent chains. Circuit breaker on repeated failures. MoE (Mixture of Experts) council for conflict resolution (e.g., Recovery says "rest" but Adaptor says "push").
Prompt Management
System Prompt Strategy (per agent)
Each agent's systemInstruction defines 6 elements:
1. Role & expertise — "You are the Workout Generator Agent, an expert exercise physiologist and program designer..."
2. Input schema — "You receive a fitness profile with goal, level, injuries, equipment, daysPerWeek, sessionDuration, focus areas."
3. Output schema — "Return a WeeklyPlan JSON object with weekNumber, startDate, endDate, days[dayIndex, workouts[workoutId, workoutName, exercises[...]]]."
4. Constraints — "Never recommend an exercise that uses equipment the user doesn't have. Never contradict a declared injury."
5. Safety rules — "If the user asks about an injury, recommend consulting a healthcare professional. Never give medical advice."
6. Tone — "Encouraging but factual. Explain your reasoning. Never overpromise results."

16 Security & Compliance
Security Architecture
🔐 Identity & Access Management
Authentication: Firebase Google SSO — single sign-on via Google OAuth. Email verification required for write operations.
Authorization: Firebase Auth uid passed as x-user-id header to all /api/fitness/* endpoints. Server validates uid presence.
Per-user isolation: Firestore rules enforce users/{uid}/... ownership — users can only read/write their own data.
Admin access: CPO role for data deletion, analytics access, user management.
🛡️ Data Security
Encryption at rest: Firebase encrypts all Firestore data at rest (AES-256).
Encryption in transit: TLS 1.2+ for all API calls. HTTPS only.
API key security: Gemini API key held server-side only in server.ts. Never shipped to browser. Client calls own API endpoints.
Secrets management: Environment variables via .env.local (not committed). GEMINI_API_KEY, Firebase config in environment.
Input validation: All API endpoints validate request body types. Firestore rules validate field types, ranges, enums.

Threat Modeling — STRIDE
S — Spoofing
User impersonation via forged x-user-id header. Mitigation: Firebase Auth tokens should be verified server-side (currently uid-only; upgrade to token verification in production).
T — Tampering
Modification of workout logs after creation. Mitigation: Firestore rules protect createdAt + workout logs from modification. Immutable fields enforced.
R — Repudiation
User denies submitting a workout or chat message. Mitigation: Server-side logging of all API calls with timestamps. Firestore audit trail.
I — Information Disclosure
Reading another user's profile/workouts. Mitigation: Firestore rules — per-user isolation. API endpoints require x-user-id matching the target uid.
D — Denial of Service
API flooding. Mitigation: Gemini rate limits. Express rate limiting (future). Firestore auto-scales. Stateless server design.
E — Elevation of Privilege
User accessing admin functions. Mitigation: No admin functions exposed in MVP. Future: CPO role via Firebase custom claims + RBAC.

ADR-001 Proposed
Full Pivot vs. Module-Add: PolyVerses → PolySync
Status✅ Accepted — Full pivot confirmed. README.md rewritten as AI Fitness Coach Platform. All docs updated. Package.json + metadata.json updated.
ContextPolyVerses is a multi-agent PM workbench. The AI fitness coach market is $6.2B growing at 25.1% CAGR with no competitor using multi-agent architecture. The question: pivot entirely to fitness, or add fitness as a module alongside the PM workbench?
DecisionFull pivot to PolySync AI Fitness Coach. Rationale: (1) Market opportunity is large and growing. ADR-002 Accepted
Multi-Agent Architecture (12 Agents) vs. Single-Model Coaching
Status✅ Accepted
ContextCoaching AI can be built as a single chat model (like Freeletics Flo) or as a multi-agent mesh where each specialist handles a domain (workout generation, recovery, chat, nutrition, form, etc.).
Decision12-agent mesh. Rationale: (1) Traceability — each decision is attributable to a specific agent, which is a feature for coaching quality trust. (2) Specialization — agents can have focused system prompts, improving quality. (3) Cost optimization — different agents use different models (Flash for cheap lookups, Pro for high-quality chat). (4) Maintainability — adding a new capability means adding a new agent, not rewriting a monolithic prompt. (5) Competitive moat — no competitor uses this architecture.
ConsequencesPositive: Higher quality, lower cost (right model per task), unique positioning, easier to extend. Negative: Higher initial complexity (12 agents to build vs. 1 chat prompt). Mitigation: PolyVerses infrastructure reuses 40% of orchestration framework. Agent system prompts are independent and can be built incrementally.

ADR-003 Accepted
Server-Side Gemini API Key + Express API Layer (vs. Client-Side Gemini)
Status✅ Accepted
ContextGemini API calls can be made from the client (React app directly to Gemini) or server-side (React → Express API → Gemini).
DecisionServer-side only. Rationale: (1) API key security — key never ships to browser. (2) Agent routing — server can assemble full user context (profile, workouts, plan, recovery) before calling Gemini. (3) Cost control — server can cache responses, rate-limit, choose model per agent. (4) Sandbox fallback — server can generate simulated responses if API key is missing, keeping the app functional. (5) Consistency — all AI calls go through the same orchestration layer.
ConsequencesPositive: Secure, contextual, cost-controlled, resilient. Negative: Server is a bottleneck — must scale horizontally. Latency added (client → server → Gemini → server → client). Mitigation: Server is stateless, scales horizontally. Gemini latency is the dominant factor; server adds minimal overhead.
